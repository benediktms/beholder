# Beholder OpenSpec

`specs/` is the normative description of current Beholder behavior. New behavior
starts as a delta under `changes/` and becomes current only after implementation
and archive.

The existing documents remain in `docs/` because they contain rationale, rejected
alternatives, measurements, and roadmap material that is not a current behavioral
contract. When they disagree with a current spec, the spec governs current behavior.
Future sections of `docs/VISION.md` remain direction until a reviewed OpenSpec change
introduces them.

## Skill workflow

Use the repository-local Codex skills generated by OpenSpec:

1. `$openspec-explore` for investigation without creating a change.
2. `$openspec-propose` for a complete proposal, delta specs, design, and tasks.
3. `$openspec-apply-change` after the artifacts are approved.
4. `$openspec-update-change` when implementation changes the plan.
5. `$openspec-sync-specs` to merge completed deltas into current specs.
6. `$openspec-archive-change` after implementation and verification.

Run `mise exec -- openspec validate --all --strict` before committing spec changes.
Run `mise exec -- openspec update` after upgrading the pinned OpenSpec version.
